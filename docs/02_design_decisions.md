# 设计取舍

## 1. 为什么不用固定长度切片

固定长度会把一张位域表从中间切断。切断之后，后半段的行有值、没有列名，
检索命中了也没法用。所以切片单位是**结构块**：小节正文一段、表格一张。

## 2. 为什么表格要独立成块

表格的语义依附于表头。把表头和若干行打包成一块，块内自带解释；
跨页续表时补表头，是同一件事的延伸。

## 3. 为什么用字符 n-gram

中文没有空格，领域缩写又多（GPAMUX1、ACQPS）。字符 n-gram 不做分词，
对"GPIO12"和"GPIO 12"这类写法差异天然鲁棒。

## 4. 为什么融合用加权而不是拼接分数

两路分数量纲不同。加权前各自按最大值归一化，alpha 可调、可解释。
RRF 也可以，但会丢掉"差多少"的信息，在需要解释分数的场景不划算。

## 5. 为什么重排要加开关

导航题问的是"在哪一节"，需要的是章节入口；CrossEncoder 倾向于把"像答案的段落"抬上来，
反而压掉入口。所以按 query 类型决定是否重排——按题型用对工具，而不是永远用更贵的模型。

## 6. 为什么评测要支持消融

只看总分无法判断某个组件有没有用。`--ablate crosslingual` 一次跑出两套指标，
差值就是这层的贡献。生产项目里同样用单变量对照，一次只改一层。

## 已知局限

- 演示语料只有 19 个 chunk，指标波动大，只能看趋势
- 重排是词覆盖近似，不是真正的 cross-encoder
- 没有向量检索：生产版用 BGE-M3，这里为了零依赖省略（见 what_is_missing）
